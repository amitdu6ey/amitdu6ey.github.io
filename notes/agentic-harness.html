Agentic Dev Harness

JPMorgan Chase, 2026 – present

Claude Code, Docker, Java, Spring Boot, Gherkin

Coding agents are only as good as the feedback loop they run in. The harness gives an agent a production-like loop on a laptop. It starts Docker-based simulations of a service's dependencies, then runs unit, contract and end-to-end suites. When something fails, the agent reads the logs, patches the code and runs again, so changes reach human review already green.

Design

Why a harness

An agent that can only run unit tests will confidently produce code that breaks at the first real integration. Shared test environments are too slow and too contended to loop on dozens of times. The harness closes that gap by giving the agent a fast, deterministic, production-shaped environment it can run as often as it needs.

The sandbox

A service's dependencies — broker, databases, cache, cloud-service emulators — start as Docker containers with seeded data and configuration of the same shape as production. Because the environment is rebuilt from scratch for each run, a failure means the code is wrong, not that someone else's test data drifted.

The test ladder

Suites run from cheapest to most realistic: unit tests, then contract tests against consumer expectations, then end-to-end scenarios written in Gherkin. Failing fast at the cheapest level keeps each loop short, and the Gherkin scenarios double as readable acceptance criteria for the reviewer.

Logs the agent can act on

The agent fixes what it can see, so the harness turns failures into evidence: the failing step, the relevant service logs around it, and the assertion that broke. With that, a failed run becomes a specific patch rather than a guess. Retries are bounded, and the agent stops and asks when it is not converging.

Guardrails

The agent works only in the sandbox and on a branch. It never touches production credentials or shared environments. Every change arrives as a pull request with its test evidence, and a human reviews it before the normal CI/CD pipeline takes over. Speed comes from removing the waiting, not from removing the review.
