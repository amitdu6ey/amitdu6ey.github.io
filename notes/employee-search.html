Design

Why names are hard

People search for colleagues the way they heard or half-remember the name: a typo, a missing letter, a different transliteration, or just the first few characters. Each failure mode needs a different matching technique, and no single analyser covers them all without flooding the results with noise.

One field, analysed four ways

  • Exact: lowercased and accent-folded, so "José" and "jose" match.
  • Prefix: edge n-grams, so "amit d" finds Amit Dubey while typing.
  • Fuzzy: edit-distance matching with fuzziness: AUTO, which allows no edits for very short terms, one for medium terms and two for longer ones, so short names don't match everything.
  • Phonetic: a sounds-alike encoding, so different spellings of the same name converge. Encoders such as Beider–Morse are designed specifically for personal names.

Ranking: precision first

All four run in one bool query as weighted should clauses. Exact beats prefix, prefix beats fuzzy, and fuzzy beats phonetic. The weighting is what makes fuzziness safe: a typo-tolerant match can surface a result, but it can never outrank someone whose name was typed correctly.

Indexing

A Spring Batch job builds the index from the source of record, with incremental updates for changes. A full rebuild can go into a fresh index and be switched over with an alias. Callers keep querying the same name while the new index is built, and the switch is atomic.
