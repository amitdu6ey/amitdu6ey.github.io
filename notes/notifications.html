Design

Intake: at-least-once in, deduplicated out

EventBridge routes producer events by rule and SQS buffers them, which gives retries and a dead-letter queue for free, but also means delivery into the platform is at-least-once. Every notification therefore carries an idempotency key from its producer. Intake records the key before doing any work, so a redelivered or retried event is recognised and dropped instead of reaching someone twice.

Policy: preferences and capabilities

Two inputs decide what happens next. User preferences say which categories a person wants and on which channels. Device capabilities say what each client can actually do. The behaviour is capability-driven: the platform shapes the payload to what the receiving client supports instead of sending one format everywhere and hoping, so older clients degrade gracefully and new features roll out per capability.

Scheduling and digests

Not every event deserves an immediate interruption. The scheduler decides between delivering now, deferring to a better time, or folding the event into a summarised digest. Digests are the main tool against notification fatigue: many low-priority events become one useful summary.

Resiliency: circuit breakers

Each delivery channel sits behind its own circuit breaker. When a channel starts failing, the breaker opens and the platform stops hammering it. Messages stay safely queued instead of being dropped, and a half-open probe lets traffic resume once the channel recovers. One channel's outage never blocks the others, and because every message carries an idempotency key, the retries after recovery cannot create duplicates.

GraphQL API and contracts

Apps read their inbox and manage settings through a GraphQL API backed by MongoDB, whose flexible documents suit per-channel payloads and settings. The schema evolves additively and fields are deprecated before they are removed.
